本版仅将浏览器直接导入的两个模块改为 .js，并同步更新引用，避免 EdgeOne 将 .mjs 返回为 application/octet-stream 后阻止页面启动。上传访迹-edgeone-pages-v2.1.zip 整包创建新部署，完成后按 Ctrl+F5 强制刷新。

skill-runtime 中的 .mjs 是供下载打包的 Node.js 脚本模板，不作为浏览器模块执行，保持原样。未更改订阅、授权、支付或技能交付逻辑；真实调用仍需后端。

验证：模块完整依赖图链接通过、静态文件结构与敏感字段检查通过、ZIP 解包校验通过。尚未替用户重新部署，也未验证新版本线上页面。

# 访迹 · EdgeOne Pages v2（任务配件安装版）

## 部署

将站点 ZIP 整包上传 EdgeOne Pages，或上传本目录内容；ZIP 根目录是 index.html，不要只上传这一个文件。它还依赖 js、css、mock-data.json 和 skill-runtime。此版本为静态前端，不需构建命令，不包含可上线的支付/订阅业务后端。不要误把两个“Skill 接入示例”ZIP 当成站点上传。

## 新流程

演示登录 → 商品订阅 → 我的 Skill 库 → 安装到助手 → 下载 Codex / WorkBuddy Skill 包。

订阅与安装不再绑定买断：订阅用户下载标准 SKILL.md + 调用脚本，在原任务中使用技能。网站输入框仅保留为折叠的模拟测试，不是工作主入口。

Codex：解压 Skill ZIP，在该包目录执行 node install.mjs。默认放入用户 .agents/skills/<技能名>，拒绝覆盖已有目录。也可自行复制技能目录。WorkBuddy：技能市场 → 添加技能 → 上传技能 → 选择 WorkBuddy 版 ZIP → 检查并启用。首次仍需要用户操作，普通网页不能静默写入助手的文件夹。

两个助手都需要 Node.js 18+ 来运行本包的客户端。实际是否自动触发由助手发现、启用状态和任务匹配决定，不能保证所有版本自动调用。

## 本版真实完成与未完成的边界

已实现：浏览器生成有效 ZIP；每个商品独立的标准技能描述、客户端、安装程序、清晰的隐私说明；真实 HTTP 调用客户端（非占位脚本）；安装防覆盖；错误处理；授权配置与源码分离。

尚需生产后端：真实登录、购买、授权签发/撤销、额度/计费、退款、卖家逻辑执行、输入生命周期和安全隔离。当前页面的交易、Key 和用量仍是浏览器模拟，不能拿来接真实服务。原项目 Node 后端也是演示程序，不能直接宣称具有生产级隔离与账务保障。

客户端契约：POST <业务服务根地址>/api/v1/run，Authorization: Bearer <真实Key>，JSON 请求 {"input":"文本"}，成功返回 {"output":"结果","meta":{}}。当前兼容原接口：最多 6000 个 UTF-16 字符，不支持直接上传二进制附件。一个 Key 应由后端绑定一个商品/订阅并检查授权，不能信任客户端声明的身份或额度。

用户在终端执行 node "已安装目录/scripts/client.mjs" --configure 后填写真实业务后端 URL 与 Key（隐藏输入）。凭据独立保存在用户 .fangji/credentials/<技能名>.json，不在 ZIP 中。--check 只验证本机配置存在，不证明服务/授权有效。为自动化也支持 FANGJI_BASE / FANGJI_API_KEY；不要把真实值写进项目、截图或聊天。

客户端不自动重试付费请求；超时可能已经执行，需查询服务端记录后决定。首次调用前，助手必须告知远程处理的数据范围；不得沿用“输入不出本机”的宣传。仅支持服务端执行型商品，本机私密型商品会阻止导出此适配器。

## 闭源与买断

订阅包是公开可读的“调用适配器”，服务端保留卖家业务代码和提示词；下载包本身不构成授权，也不提供解密密钥。订阅到期由服务端拒绝调用，不能靠前端隐藏按钮保护。

买断包应由真实后端交付卖家完整的 SKILL.md、脚本和资源；本静态演示没有真实商品源码，原有示例源文件不代表真正交付。

如果一个技能必须把完整核心提示词交给买家模型阅读，就不可能同时对该模型隐藏。远程执行也不保证逻辑无法从输出推测。要兼顾闭源与任务内协作，应卖远程执行能力，而不是把加密提示词和解密密钥一起下发。
